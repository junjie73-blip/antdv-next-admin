# CLI

In one sentence: **there is no standalone scaffolding CLI (no `plop`/`gen` command exists). "CLI" here means pnpm scripts + turbo + two home-grown tools (`vsh`, `turbo-run`). Every command below was verified against the actual package.json files.**

## Prerequisites

| Item | Requirement | Source |
| --- | --- | --- |
| Node | `>=22.0.0` | root `package.json` `engines` |
| pnpm | `10.12.4`, and pnpm-only (`preinstall: npx only-allow pnpm`) | root `packageManager` |
| Install | `pnpm install` (`bootstrap` is an alias); `postinstall` runs `stub` across sub-packages | root scripts |

## Daily development

```bash
pnpm dev              # turbo-run dev: interactive task picker over turbo
pnpm dev:web          # pnpm --filter @antdv/web run dev (vite; port from VITE_PORT, set to 6080 in .env.development)
pnpm preview          # turbo-run preview
```

The mock server needs no separate start: with `VITE_MOCK=true` (default in `.env.development`) the embedded `vite:mock-server` plugin boots Nitro on port 5320. To run it standalone:

```bash
pnpm --filter @antdv/backend-mock dev     # nitro dev
```

## Build

```bash
pnpm build            # cross-env NODE_OPTIONS=--max-old-space-size=8192 turbo build
pnpm build:docker     # scripts/deploy/build-local-docker-image.sh
pnpm --filter @antdv/web build            # single package build
```

::: warning Bundle analysis is an env switch, not `build:analyze` The root `build:analyze` script points at a turbo task that **is not defined** in `turbo.json`, so it fails. The working path is `VITE_VISUALIZER=true pnpm build` — `createVisualizerPlugin` then mounts `vite-bundle-analyzer` (see [Vite config](/en/guide/project/vite)). :::

The turbo graph (`turbo.json`): `build / dev / type-check / test:unit / test:e2e` all `dependsOn ^build`; `dev / test:e2e / clean` skip caching; `build` outputs cover `dist / .output / .nitro / .vitepress/dist`. After editing `packages/*`, the browser still reads the sub-package `dist` — if turbo's cache mis-times, you get "changed nothing happened"; restarting dev is a fixed step in the checklist at the end of [Testing](/en/guide/project/testing).

## Quality gates

```bash
pnpm check            # check:circular && check:dep && check:type && check:cspell
pnpm check:type       # turbo run type-check (apps/web runs two vue-tsc projects: app + vitest)
pnpm lint             # vsh lint (oxlint/oxfmt/eslint/stylelint; see the Conventions page)
pnpm format           # vsh lint --format
pnpm publint          # vsh publint: verify package export surfaces before publish
pnpm test:unit        # turbo run test:unit
pnpm test:e2e         # turbo run test:e2e
pnpm test:e2e:install # playwright install (three browser engines; required on first run)
pnpm test:benchmark   # vitest bench --run
```

`vsh` is the bin from `scripts/vsh` (`pnpm exec vsh <cmd>`) with five subcommands: `check-circular / check-dep / code-workspace / lint / publint`.

## Codegen (all happen inside vite; no separate command)

| Artifact | Generated by | Notes |
| --- | --- | --- |
| `apps/web/types/router.d.ts` | unplugin-vue-router (`routesFolder: src/views`) | typed conventional routes |
| `apps/web/types/auto-imports.d.ts` / `components.d.ts` | unplugin-auto-import / unplugin-vue-components | checked into git; pass `VITE_WRITE_DTS=false` to skip the writes when the flaky dts write kills dev servers (see [Vite config](/en/guide/project/vite)) |
| `apps/web/types/env.d.ts` | `vite-plugin-env-parse` | typed env variables |

These refresh with dev/build — **never hand-edit them**.

## Versioning and release

```bash
pnpm commit           # czg: prompted commit (type/scope/subject)
pnpm changeset        # scaffold a .changeset/*.md
pnpm version          # changeset version && pnpm install --no-frozen-lockfile
pnpm release          # build && changeset publish
```

Details in [Changesets](/en/guide/project/changeset).

## Misc

- `pnpm docs:dev / docs:build / docs:preview` — the VitePress site, its own workspace package `@antdv/docs`, outside the app build.
- `pnpm update:deps` — `taze -r -w` lists upgradable deps; `pnpm catalog` — `pnpm dlx codemod pnpm/catalog` syncs catalog references.
- `pnpm clean / reinstall` — `scripts/clean.mjs`; the latter also deletes the lockfile.
- `pnpm sync-upstream` — home-grown script driven by `sync-upstream.json`.
- There is no bare `test` or root `coverage` task; for coverage go to `apps/web` and run `pnpm exec vitest run --coverage`.
